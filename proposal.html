Health Aid Proximity-Sensing Webcam

Project Concept & Motivation

I aim to complete the development of a proximity-sensing webcam that notifies users when they are too close to their laptop or monitor screen.
Based on real-time interaction between the product’s hardware and firmware, users receive a visual indicator signifying their distance from the screen.
The output appears as a color-coded overlay using BetterTouchTool (BTT) on macOS.

Bill of Materials

  • 3D-printed shell for webcam housing
  • Adafruit VL53L1X Time-of-Flight Distance Sensor
  • Adafruit QT Py – SAMD21 Dev Board with STEMMA QT
  • STEMMA QT / Qwiic JST SH 4-Pin Cable (50 mm)
  • USB-C data cable

Timeline & Contingency Plans

Week 7 (Current): Hardware Assembly & Initial Firmware

Goals

  • Wire the QT Py ↔ VL53L1X using a STEMMA QT cable.
  • Upload and verify the distance-reporting Arduino sketch (CLOSE / MEDIUM / FAR output).
  • Begin tuning thresholds for real screen-use distances (≈18–30 inches).
  • Confirm stable serial output via the Arduino IDE Serial Monitor.

Deliverables

  • Working breadboard prototype
  • Calibrated firmware for the setup
  • Serial output that matches user proximity

Contingency

  • If readings fluctuate, add median or exponential-moving-average smoothing.
  • If the sensor misreads near glossy screens, slightly tilt the sensor downward.

Week 8: BTT Integration & Bridge Script

Goals

  • Write and test the Python → BTT webhook bridge (btt_bridge.py).
  • Enable the BTT Web Server and create named triggers (CLOSE, MEDIUM, FAR).
  • Design and test visual overlays or tint indicators in BTT.
  • Verify real-time response between proximity changes and BTT overlays.

Deliverables

  • Running bridge script with printed console logs
  • Functional BTT overlays triggered by distance zones

Contingency

  • If BTT triggers lag, reduce delay() in firmware or Python loop.
  • If the serial port changes on reconnect, add auto-detection to the script.

Week 9: Enclosure Design & System Refinement

Goals

  • 3D-model a compact shell that mounts above a laptop or external monitor.
  • Print and fit-test the enclosure; adjust the aperture for the VL53L1X sensor.
  • Optimize the sensor’s downward angle (~10–15°).
  • Conduct informal user testing with classmates to assess comfort and clarity.

Deliverables

  • Fully enclosed working prototype
  • User feedback and final threshold adjustments

Contingency

  • If the print fit is off, re-measure and re-print smaller components.
  • If reflection interferes, coat the interior matte black or add a thin foam baffle.

Week 10 → Finals Week: Documentation & Presentation

Goals

  • Create a complete HTML documentation page (schematic, firmware, photos, etc.).
  • Record a short demo video showing overlays responding to proximity zones.
  • Prepare a concise presentation deck summarizing concept, motivation, and system workflow.

Deliverables

  • Final webpage and demo video
  • Presentation ready for showcase

Contingency

  • If hardware issues occur on demo day, use a pre-recorded demo video.
  • Keep both .ino and Python files versioned in GitHub for redundancy.
